# Contributing to Formato24 Open Source

Thank you for helping build useful, accessible open technology. Contributions can include code, documentation, testing, design, resource curation, and review.

These guidelines apply across the organization unless a repository provides more specific instructions. Participation follows our [Code of Conduct](https://github.com/formato24-os/.github/blob/main/CODE_OF_CONDUCT.md).

## Start with the problem

1. Read the target repository's README, license, contribution instructions, and open issues.
2. Search existing issues and pull requests before opening a new one.
3. Use an issue in the affected repository for a bug, feature, or documentation improvement. Include enough context for someone else to understand and reproduce the problem.
4. Discuss substantial changes before implementation. Small, focused fixes can go directly to a pull request.

Use [community issues](https://github.com/formato24-os/.github/issues/new/choose) for organization-wide proposals or ideas that do not yet have a repository. The project proposal form also accepts monthly project ideas. An idea is not scheduled until maintainers record a selection.

Public issues and pull requests must not contain credentials, private data, or undisclosed vulnerabilities. Follow the [security policy](https://github.com/formato24-os/.github/blob/main/SECURITY.md) for sensitive security reports.

## Prepare a change

- Fork the repository and work on a focused branch, or use a branch if you have contributor access.
- Follow the repository's existing conventions and documented setup instructions.
- Keep the change limited to one purpose. Explain unrelated ideas in separate issues.
- Update documentation and examples when behavior changes. Add or update meaningful tests when applicable.
- Run the checks documented by the repository and report their results. If a check cannot run, explain the limitation.
- Use clear English for shared documentation and issue summaries. You do not need perfect English to participate.
- Credit sources and verify that submitted code, text, and assets can be shared under the target repository's license.

For the `.github` repository, run the documented [validation commands](https://github.com/formato24-os/.github/blob/main/docs/validation.md) and review Markdown rendering. Shared policies should use absolute links to this repository so they also work when displayed in other projects. Repository-specific validation instructions take precedence in other projects.

## Open a pull request

Use a descriptive title. Explain the problem, the resulting behavior, related issues, and how you verified the change. Include screenshots when a visual change benefits from them. Draft pull requests are welcome for work in progress.

Respond constructively to review feedback. Maintainers may request a smaller scope or additional evidence before merging. Review and response times depend on contributor availability; opening a pull request does not guarantee acceptance or a delivery date.

## Help review

Check whether the change addresses its stated problem, remains understandable, and has appropriate verification. Suggest concrete improvements and distinguish required fixes from optional preferences. Maintainers are responsible for merge decisions under the [governance model](https://github.com/formato24-os/.github/blob/main/GOVERNANCE.md).

Need help choosing where to contribute? See [Support](https://github.com/formato24-os/.github/blob/main/SUPPORT.md).
